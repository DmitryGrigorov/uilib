# Developer documentation

The table is composed of these primary components:

- `Table` is the root component.
- `Header` renders the table header.
- `ColumnsRow` renders the column-header row.
- `Column` renders an individual column header.
- `Footer` renders the table footer.
- `Rows` renders the table rows.
- `Row` renders an individual row.
- `Cell` renders table cells.

Supporting hooks in `/hooks`:

- `useColumnApi` builds the column API, including column pinning.
- `useTableApi` builds the main table API, including programmatic pagination.

The table exposes its API through `useImperativeHandle`, replacing the standard ref value with a custom interface generated by `useColumnApi` and `useTableApi`.

## Table store (`TableContext/tableService.tsx`)

The observable store implements the core table-data behavior.

It contains the following state:

- `rowsPerPage`: number of rows displayed on each page.
- `currentPage`: current page.
- `filteredRows`: rows that pass active filters.
- `sortParams`: sorting settings.
- `rightPinnedColumnsLength`: number of columns pinned on the right.
- `leftPinnedColumnsLength`: number of columns pinned on the left.
- `tableWithPinnedColumns`: whether the table contains pinned columns.
- `rowModel`: either `client` or `server`. With `client`, the `Table` component handles filtering, sorting, search, and related data operations. With `server`, the consumer handles those operations, often through a backend, and the table reports the relevant parameters such as the search query.
- `rowData`: all available rows with `rowModel="client"`, or the currently displayed rows with `rowModel="server"`.
- `rowsNodes`: display metadata, IDs, and other state for the rendered rows.
- `rowsSelection`: row-selection state.
- `showRows`: rows currently displayed.
- `filterParams`: active filter settings.
- `searchColumns`: column-search settings.
- `globalSearch`: global search query.
- `pinnedRows`: pinned rows.
- `columns`: external column definitions, initially read from props.
- `localColumns`: working column definitions. All runtime column actions and updates apply here.
- `callbacks`: component callbacks invoked by store actions.
- `defaultColumn`: shared settings for every column.

Displayed data uses a `Map` for efficient keyed access. The store implements the following actions.

### `setRowData`

Accepts `rowData`, `getRowId`, and `columns`. It transforms data received through props or the `setRowData` API, creates IDs with the supplied `getRowId` function or `getRowUniqId`, and adds computed values used by the rendered table. It runs during table initialization and when `rowData` or `columns` changes.

> Prefer the API method when updating `rowData` instead of mutating props.

### `setRowNodes`

Creates the initial row metadata.

### `changePage`

Writes the new page to the store and rebuilds `showRows` with `getFirstPageRowsHelper`.

### `changeRowsPerPage`

Updates the number of displayed rows, resets the current page, and rebuilds `showRows` with `getFirstPageRowsHelper`.

### `searchRows`

Filters data for either column-level or global search. It accepts:

```ts
search: string; // Search query
column?: TLocalColumn<TData, TValue>; // Column data for a column-specific search
```

### `setRowNode`

Runs when a row renders and replaces its initial row-node metadata with values for that specific row.

### `selectAllRows`

Updates `rowsNodes` so every row is selected. It runs when the header checkbox is selected and calls the `onSelectionChanged` prop with all selected row nodes.

### `setSorting`

Sorts rows using the action's `name` and the column's `comporator`. Sorting runs inside `Table` only when `rowModel="client"`; with `rowModel="server"`, the consumer is responsible for sorting.

### `setColumns`

Stores external definitions in `columns`, identifies columns pinned by default, and produces `localColumns`. The working order is left-pinned columns, unpinned columns, then right-pinned columns. It runs during initialization and can later be called through the `setColumns` API.

### `setDefaultColumn`

Stores shared column defaults in `defaultColumn`. Individual entries in `columns` can override these values.

### `pinningColumn`

Updates `localColumns` to pin a column on the left or right. It also calls `onChangePinnedColumn` with the pinned column, its `pinnedDirection`, and `isPinned=true`.

### `unpinningColumn`

Updates `localColumns` to unpin a column. It also calls `onChangePinnedColumn` with the column, its former `pinnedDirection`, and `isPinned=false`.

### `setFilter`

Accepts a column and its active filters. Filtering runs locally only with `rowModel="client"`; otherwise the store retains the filter settings for external handling. Client-side filtering calls the column's `filterFunc` for every row and writes matching rows to `filteredRows`, which then feeds the paginated output.

### `setPinnedRows`

Pins row nodes at the beginning of the table, regardless of the current page. Passing an empty array or `undefined` clears pinned rows.

### `setUnpinnedRow`

Unpins a specific row.

### `setPinnedRowData`

Pins supplied data in addition to rows already present in the table. It runs for the `pinnedRowData` prop or through the `rowsPinnedApi` method; the API is the preferred approach.

### `setCallbacks`

Stores component callbacks so store actions can invoke them.

## Supporting functions (`TableContext/helpers.ts`)

### `getFirstPageRowsHelper`

Selects displayed data according to pagination state.

### `getSearchColumn`

Searches within a specific column.

### `getGlobalSearch`

Searches all table data.

## `Table` component

The root component initializes table state and owns table-wide handlers. During initialization it calls:

1. `changeRowsPerPage` to store the initial `paginationPageSize`.
2. `setColumns` to store definitions and generate unique column IDs.
3. `changePage` to store the page from `paginationCurrentPage`.
4. `setRowData` to store row data.
5. `setRowNodes` to generate row metadata from the stored data.
6. `setPinnedRowData` first with an empty array to clear stale data, then with the new pinned rows.
7. `setCallbacks` to store `onChangePinnedColumn` and `onSelectionChanged` for direct use by the store.

It also initializes the table and column APIs through `useTableApi` and `useColumnApi`.

### Pinned-column presentation

`useMultipleResizeObserver` and `useLayoutEffect` calculate the widths of left- and right-pinned columns. These measurements support visual edge treatments during horizontal scrolling. `handleScroll` controls the shadows shown beside pinned columns.

## `Header` component

Renders the table header when present. It also invokes the `SEARCH_ROWS` action when the external `search` prop changes or `handleSearch` runs.

## `ColumnsRow` component

Renders column headers from `localColumns`, excluding definitions whose `isHidden` property is set.

## `Rows` component

Reads `showRows`, `rowsNodes`, `pinnedRows`, and `localColumns` from the store. It renders pinned rows first, followed by regular data rows.

## `Column` component

Renders a column header from its definition and store state. It can call these store actions:

- `selectAllRows` to select every row.
- `pinningColumn` to pin the column.
- `unpinningColumn` to unpin the column.

## `Row` component

Renders a table row and calls `setRowNode` during initialization to store its metadata. It contains:

- `PinCell`, shown when `isPinningRows=true`.
- `CheckboxCell`, shown when `isCheckboxSelection` enables row selection.

It maps `localColumns` to `PlusCell` or `ArrowCell` for the corresponding special column types, and to `Cell` for regular values.

## `Cell` component

Renders primary table data according to the cell types supplied through `columns`.

## `RowNested` component

Renders additional row data. With `viewTypeDetail="table"` and `detailRowOptions`, it renders a nested table. With `viewTypeDetail="info"`, it renders the custom component returned by `detailRowRenderer`.
